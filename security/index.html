Security policy

How we keep the app secure and how to report a vulnerability.

How the app is built

  • The app is built on Atlassian Forge. TooSolv Studio operates no external app servers.
  • It requests read:page:confluence to read the open page, storage:app to keep export-history metadata in Forge hosted storage, and report:personal-data to handle Atlassian privacy deletion and refresh instructions.
  • Files are created in the browser. Table-cell content stays within Atlassian and your device.
  • Forge history records contain metadata only, never table-cell content or exported files, and remain separated by app installation and signed-in account.
  • The app follows Atlassian's security requirements for Marketplace apps.

Does an export app make it easier to take data out?

It is a fair question, so here is the precise answer. In its current workflow, the app requests the page the user has open and does not enumerate or search the site. The read:page:confluence permission technically allows it to read pages that the signed-in user may access. It does not send page content to a vendor server. The additional storage:app permission stores export-history metadata inside Atlassian Forge. If your policy is that content must not leave Confluence, use page and space permissions and Atlassian's data security policies, which can block this app in named spaces.

Scope

This policy covers the TableFlow: Excel & CSV Export for Confluence app, this website (toosolv.github.io) and the address contact@toosolv.com. It does not cover Atlassian's own platform, Confluence Cloud or the Atlassian Marketplace; please report those through Atlassian's own vulnerability programme.

Safe harbour

If you report a vulnerability in good faith, keep to the scope above, do not access, change or delete data that is not yours, and give us reasonable time before making details public, we will not take legal action against you and will treat your report as authorised research.

Report a vulnerability

Please email contact@toosolv.com with the subject "Security report". Include the steps to reproduce and the impact you see. Please do not share details publicly until a fix is released.

What happens next

  • We send a first response within 3 business days, usually sooner.
  • We fix confirmed vulnerabilities within the timeframes of Atlassian's Security Bug Fix Policy for Marketplace apps.
  • We tell you when the fix is released.
